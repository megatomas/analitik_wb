## Что нужно сделать для работы с реальными данными:

### 1. Установите зависимости для серверных функций

```bash
npm install @vercel/node
```

### 2. Настройте переменные окружения в Vercel

В дашборде Vercel → Settings → Environment Variables добавьте:

```
VITE_API_BASE_URL=/api
```

### 3. Задеплойте с серверными функциями

```bash
git add .
git commit -m "Add WB API server functions"
git push
```

Vercel автоматически задеплоит серверные функции из папки `api/`.

## Как это работает:

### Пользовательский flow:

1. **Регистрация** → Пользователь создаёт аккаунт
2. **Ввод API-ключа** → Пользователь вводит свой API-ключ WB
3. **Запрос к дашборду** → Фронтенд делает запрос к `/api/wb-sales`
4. **Прокси-сервер** → Серверная функция получает данные от WB API с ключом пользователя
5. **Возврат данных** → Реальные данные отображаются на дашборде

### Архитектура:

```
Frontend (React)
    ↓
    ↓ /api/wb-sales (с Authorization: Bearer <user_api_key>)
    ↓
Vercel Serverless Function (api/wb-sales.ts)
    ↓
    ↓ Fetch с ключом пользователя
    ↓
Wildberries API (statistics-api.wildberries.ru)
    ↓
    ↓ Реальные данные
    ↓
Frontend (отображение)
```

## Безопасность:

## Если данные не загружаются:

### Проверьте:
- API-ключ введён правильно (начинается с `eyJ...`)
- У ключа есть права на "Статистику" и "Товары"
- Уровень доступа: "Только чтение"
- Ключ активен (не отозван)

### Логи:
- Откройте консоль браузера (F12)
- Посмотрите ошибки в Network tab
- Проверьте логи в Vercel Dashboard → Functions

## Дополнительные возможности:

### Кэширование (опционально):

Можно добавить кэширование для уменьшения нагрузки на WB API:

```typescript
// В api/wb-sales.ts
const CACHE_TTL = 15 * 60 * 1000; // 15 минут
const cache = new Map();

// Перед запросом к WB API
const cacheKey = `sales_${apiKey}`;
const cached = cache.get(cacheKey);
if (cached && Date.now() - cached.timestamp < CACHE_TTL) {
  return res.status(200).json(cached.data);
}
```
