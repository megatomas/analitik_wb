# 🔧 Исправление ошибки 429 (Too Many Requests)

## Проблема

При загрузке данных возникала ошибка 429:
```
POST https://analitik-wb.vercel.app/api/wb-proxy 429 (Too Many Requests)
```

### Причина

Функция `getStockRecommendations` делала **3 параллельных запроса** через `Promise.all`:
1. Остатки на складах WB
2. Остатки на складах продавца  
3. Заказы (Order Feed)

Это превышало лимиты:
- **Vercel Function**: ограничивает количество одновременных запросов
- **WB API**: лимит 1 запрос в 20 секунд для персонального токена

## Решение

### 1. Увеличили время кэширования

**Vercel Function** (`api/wb-proxy.ts`):
```typescript
const CACHE_TTL = 20 * 60 * 1000; // 20 минут (было 10)
```

**Клиент** (`src/services/wbApi.ts`):
```typescript
const CACHE_TTL = 15 * 60 * 1000; // 15 минут (было 5)
```

### 2. Изменили на последовательные запросы

**Было** (параллельно):
```typescript
const [stocksWB, stocksSeller, ordersResponse] = await Promise.all([
  getStocksWB(),
  getStocksSeller(),
  fetchViaProxy('POST', WB_API.orderFeed, {...}),
]);
```

**Стало** (последовательно с задержками):
```typescript
// Задержка между запросами (2 секунды)
const delay = (ms: number) => new Promise(resolve => setTimeout(resolve, ms));

// 1. Получаем остатки на складах WB
const stocksWB = await getStocksWB();
await delay(2000); // Ждём 2 секунды

// 2. Получаем остатки на складах продавца
const stocksSeller = await getStocksSeller();
await delay(2000); // Ждём 2 секунды

// 3. Получаем заказы
const ordersResponse = await fetchViaProxy('POST', WB_API.orderFeed, {...});
```

## Как это работает

### До исправления:
```
Время 0s:  → Запрос 1 (остатки WB)
Время 0s:  → Запрос 2 (остатки продавца)  ❌ 429
Время 0s:  → Запрос 3 (заказы)            ❌ 429
```

### После исправления:
```
Время 0s:  → Запрос 1 (остатки WB)        ✅
Время 2s:  → Запрос 2 (остатки продавца)  ✅
Время 4s:  → Запрос 3 (заказы)            ✅
```

## Лимиты WB API

### Персональный токен:
- **Order Feed**: 1 запрос в минуту
- **Stocks Report**: 3 запроса в минуту (20 секунд между запросами)

### Наше решение:
- Задержка 2 секунды между запросами
- Кэширование на 15-20 минут
- Последовательные запросы вместо параллельных

✅ **Стабильная работа** — предсказуемое поведение  

## Технические детали

### Кэширование на двух уровнях:

1. **Vercel Function** (20 минут):
   - Кэширует ответы от WB API
   - Снижает нагрузку на WB API
   - Работает для всех пользователей

2. **Клиент** (15 минут):
   - Кэширует данные в браузере
   - Мгновенная загрузка при повторных запросах
   - Работает для каждого пользователя отдельно

### Последовательные запросы:

```typescript
// Функция задержки
const delay = (ms: number) => new Promise(resolve => setTimeout(resolve, ms));

// Последовательные запросы с задержками
const stocksWB = await getStocksWB();
await delay(2000); // 2 секунды

const stocksSeller = await getStocksSeller();
await delay(2000); // 2 секунды

const ordersResponse = await fetchViaProxy(...);
```

## Если ошибка 429 всё ещё появляется

### Возможные причины:

1. **Кэш не работает**
   - Проверьте что `CACHE_TTL` установлен правильно
   - Проверьте логи Vercel Function

2. **Запросы всё ещё параллельные**
   - Проверьте что используется `await delay(2000)`
   - Проверьте что нет `Promise.all`

3. **Лимиты WB API изменились**
   - Увеличьте задержку до 3-4 секунд
   - Увеличьте время кэширования до 30 минут

### Решение:

```typescript
// Увеличьте задержку
await delay(3000); // 3 секунды вместо 2

// Увеличьте кэш
const CACHE_TTL = 30 * 60 * 1000; // 30 минут
```

**Решение:** Последовательные запросы с задержками + увеличенное кэширование  
**Результат:** Стабильная работа без ошибок 429
